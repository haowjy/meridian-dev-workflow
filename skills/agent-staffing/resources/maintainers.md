# Maintainers

## Documentation

@kb-lead: maintain content in `.context/` and the KB. For development work, `/post-dev` runs it when the change settles; spawn it directly for research or explicit knowledge maintenance. Brief it as its description asks, adding design artifacts so it can compare intent with implementation. It reorganizes what it touches.

@kb-maintainer: reorganize documentation and repair links, diagrams, and naming. Use when a whole documentation tree has become hard to navigate. Pass the target tree. It flags stale or contradictory content for the content owner rather than deciding its truth. Use @explorer to compare documentation claims with code.
