# Model Selection

Check the live catalog for model capabilities, cost, and availability. Choose
the least expensive available option that meets the task's requirements.

## Implementation and Execution

Prefer **Luna → DeepSeek → Sonnet** for general implementation and execution.
Luna and DeepSeek can own substantial, coherent engineering objectives; hand them
whole ones rather than mechanical fragments.

Give workers the outcome, relevant context, constraints, and acceptance checks,
not an edit script.

## When a Larger Model Earns Its Cost

| Need | Preferred model |
|---|---|
| Difficult technical analysis or technically demanding work | Sol |
| Consequential decisions and important communication | Astra |
| Deep, sustained implementation work | Opus |

Assess writing quality separately from coding ability. A focused writing pass
can avoid using a larger model for the whole task; pass the source evidence
and audience. If judgment and writing cannot be separated, choose for both
from the start.

## Capability and Escalation

For screenshots and rendered interfaces, verify image input and the required
tools on the selected route. Browser operation and visual design taste are
different capabilities. Use training-eligible endpoints, including Muse
Contributor, only when the submitted context is appropriate for those terms.

## Escalation

Escalate on evidence, not a guess at difficulty. When a worker ran out of
depth, retry on Opus with its report and evidence, so the retry builds on
what was learned. Start on Opus for concerns known to be hard:
concurrency, data integrity, ownership across modules. Without Opus, use
Sol.
